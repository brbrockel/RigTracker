# Independent Review — October 2026

A full review of RigTracker (API, web, platform, deployment), measured against the patterns built for TeeMate. Three independent reviews (security, web/UI, platform) were run and their key findings re-verified by hand. Line references are as of commit `32b85f0`.

## Executive Summary

- **The app is currently exposed.** Every GET route and every upload is readable without signing in, and any Google account can sign in with write access because no allowlist is set. People records (DOB, phone, address, emergency contacts) are among the open routes. Combined with unrestricted uploads served from the app's own origin, this is a full compromise path from the internet.
- **The deployment leaks and over-exposes.** The Google client secret and mongo-express password are in plaintext in the homelab stack file; Mongo runs without auth on a published port; there are no backups.
- **The stack is two to four major versions behind.** Node 18 (EOL), Nest 10, Express 4, Mongoose 7, React 18, Vite 5. `pnpm audit --prod` reports 36 vulnerabilities (1 critical, 15 high).
- **There are no quality gates**: no tests, lint, format, typecheck in the web build, or CI.
- **The UI works but is desktop-first**, antd-based, without dark mode, with copy-pasted data loading and inconsistent error handling.

Recommendation: fix security first (Phase 0, small), then bring the tooling and container in line with TeeMate, then rebuild the web UI on TeeMate's design system. Moving to PostgreSQL is worthwhile for a single stack across both apps, but should come after the hygiene work, not before.

## 2. Security findings (API)

| # | Sev | Location | Problem | TeeMate pattern |
|---|---|---|---|---|
| S1 | High | `docker/nginx.conf:9-13, 23-24` | nginx reflects **any** `Origin` with `Allow-Credentials: true`, overriding the Nest allowlist; Nest's own default is `enableCors()` (wildcard), producing duplicate ACAO headers. | No CORS in nginx; allowlist only, none when unset (`api/src/app.ts`). |

| S4 | Medium | `gear.service.ts:20-21`, `audit.service.ts:53-54` | NoSQL operator injection via query strings (`?rigId[$ne]=x`, `?personId[$regex]=`). | zod query schemas, or `mongoose.set('sanitizeFilter', true)`. |
| S5 | Medium | `auth.service.ts:94, 243-245` | `email_verified` not checked; upsert matches `googleId OR email` and overwrites `googleId` — account takeover by a Google account carrying a matching unverified email. | S6 | Medium | `auth.service.ts:111-116`, `session.schema.ts:6` | Session tokens stored in plaintext; no "sign out everywhere"; no admin sign-out/deactivate. | SHA-256-hashed tokens (`auth/tokens.ts`), `revokeAllForUser`. |
| S7 | Medium | global | No rate limiting (OAuth callback, uploads, writes). | `ThrottlerGuard` keyed on `CF-Connecting-IP`. |

| S10 | Medium | `auth.controller.ts:117-123` | Client IP from first `X-Forwarded-For` value (client-controlled). | `common/client-ip.ts` with Cloudflare header + `trust proxy`. |

## 3. Correctness bugs

**API**
- `findByIdAndUpdate` runs without `runValidators`, so schema rules (e.g. `gear.notes` maxlength) are skipped on update (`gear`, `rigs.service.ts:53`, `people.service.ts:50`, `events.service.ts:30`).
- `Person` has no `displayName` field; `normalize_people_names.ts:22` never saves it yet reports every person updated; `rigs.service.ts:29` and `migrate_primary_user.ts:38` read a field that never exists.
- `import_csv_mongo.ts`: `'reservserialnumber'` typo (:85) sends reserve serials to `customFields`; `pastNaming` not in schema (:107); `primaryUserId` stored as ObjectId vs string (:119); re-running duplicates every person.
- Deleting a person leaves `rigs.primaryUserId` and `gear.assignedPersonId` dangling (`people.service.ts:55-59`); gear pointing at a missing rig can never be edited again (`gear.service.ts:98-100`).
- Container start always waits the full 60 s: the entrypoint polls `GET :4000/`, which 404s (`docker-entrypoint.sh:24`).
- The `viewer` role is unreachable (`user.schema.ts:11` vs `auth.service.ts:263`).
- `dotenv` is a dependency but never loaded.

**Web**
- Admin deep links (`/settings`, `/audit`) always bounce to `/` on a fresh load because `loadingAuth` is ignored (`App.tsx:226-227`).
- Rigs, People, Events and EventDetail call `.json()` without checking `res.ok`; an error body becomes "data", crashing `.map` or filling the form with an error object. `EventsPage.load` has no `catch`.
- Phone validation parses without a country (`PeoplePage.tsx:220`), save parses with one (`:74`): national-format numbers are rejected.
- Delete passes `r._id` while `rowKey` falls back to `id` (Rigs/People/Gear) — can send `undefined`.
- `EventDetailPage.tsx:101-110` calls a setter inside a state updater with stale state (double-runs under StrictMode); videos upload to `/uploads/image`; video primaries render as `<Image>`.
- Gear "Actions" column shows without rights; admins can demote themselves (`SettingsPage.tsx:98`); audit load failures are silent and column filters only apply to the current 50-row page.
- `isVerySmall = screens.xs === false` is inverted (`RigsPage.tsx:27`); `screens` starts empty so `isMobile` is true on first render and the layout jumps (`App.tsx:104`).

## 4. Platform and tooling

**Dependencies** (RigTracker → TeeMate/current): Node 18 → 24 · TypeScript 5.9 CJS → 6.0 ESM/NodeNext · Nest 10 → 12 · Express 4 → 5 · Mongoose 7.8.9 → 8+ (or Drizzle) · React 18 → 19 · Vite 5 → 8 · react-router-dom 7.15 → 8 · ts-node-dev → `node --watch` · dotenv/raw `process.env` → zod-validated `config.ts`. `xlsx@0.18.5` (abandoned on npm, CVEs) is only used by one import script — remove it.

**Container and build** (`Dockerfile`, `docker/`, `build.sh`)
- `--no-frozen-lockfile --shamefully-hoist`; `packages/shared/package.json` not copied; the whole dev `node_modules` shipped to runtime.
- nginx + Node in one container with a curl wait loop; Nest can already serve the SPA (`main.ts:52-76`), so nginx is redundant. Move to TeeMate's single process with `WEB_DIST`.
- No `USER`, no `HEALTHCHECK`, no `/api/health`, hardcoded port 4000.
- `build.sh` does `docker stack rm` then redeploy (full outage each deploy) and pushes a mutable `combined-latest` tag. Use `stack deploy` rolling updates and versioned tags with `APP_VERSION`.
- Traefik labels sit at service level; the Swarm provider reads `deploy.labels`. Verify how routing actually works today.
- Leftovers: `web/docker-entrypoint.sh`, committed `tools/import_run.log`, empty `api/src/packs/`, workspace path to `../../../../srv/homelab-data`.

**Data layer** — ~280 documents (gear 112, rigs 9, people 9, events 2, users 3) plus 216 MB of uploads.
- Every field optional; no enums; relationships are untyped strings with no `ref` or index; rig embeds component serials while gear separately points at rigs (two sources of truth); rig number/name not unique; duplicate `expiresAt` index; no audit index.
- Migrations are ad-hoc `ts-node` scripts with no version table, not in the image.

**Quality gates** — none: no tests, ESLint, Prettier, `.editorconfig`, `.nvmrc`, `.env.example`, CI, or `check` script. `@rigtracker/shared` exports one stale type nobody imports, while phone/email validation is duplicated in API and web.

**Docs** — `Development.md` mixes dev and deploy, says Node 20+ (image is 18), lists EH-001 as "planned next", and documents the exposed port 4000 as a feature. Missing compared with TeeMate: `Security.md`, `Deployment.md`, `TestPlan.md`, `Plan.md`.

### Mongo or PostgreSQL?

Move to **PostgreSQL 18 + Drizzle**, as a later phase.
- *For:* one stack across both apps (reuse TeeMate's migrate-at-start, zod config, Docker secrets, backup sidecar, CI Postgres service); real foreign keys with `ON DELETE SET NULL` for gear → rig/person; unique serial and rig number; rig components modelled as gear rows (removes the dual source of truth); append-only audit enforced by trigger; mongo-express goes away. `customFields` maps to `jsonb`.
- *Cost:* the ETL is a one-off ~100-line script for 280 documents; the real work is rewriting five services and the auth/session store (M–L).
- *If staying on Mongo:* upgrade Mongoose, enable auth, add zod DTOs/refs/indexes, versioned `migrate-mongo`, `mongodump` sidecar. It works, but leaves two operational stacks to run.

## 5. Web UI — moving to TeeMate's design

**Today:** antd `Layout/Sider/Menu` shell with a hamburger on phones and an overflowing 64px header; each page has its own `useState/useEffect` + raw `fetch` (no caching; detail pages re-download every list); `any` types throughout; `API_BASE` redefined in 10 files; `resolveImageUrl` ×4, `uploadImageFile` ×3, `personName` ×3, image picker block ×2; full month calendar on phones; tables on phones in Settings/Audit; hardcoded colours, no dark mode, an unloaded font, a global `min-height:44px` rule leaking into antd; main chunk 190 KB gz; no `vite.config`, no typecheck, no tests. No `dangerouslySetInnerHTML` or tokens in JS — the httpOnly cookie approach is right.

**TeeMate's design system** (to copy from `teemate/web/`):
- Shell `components/AppLayout.tsx`: sticky top header with inline links on `md+`, fixed bottom tab bar below `md`, `max-w-5xl` content, safe areas, admin pages in the account dropdown.
- Tokens in `index.css` (oklch variables, `.dark`), `lib/theme.ts` + `public/theme-init.js` (system/light/dark, no flash).
- UI kit `components/ui/*` (button, card, dialog as bottom sheet on phones, dropdown-menu, input/select/label, alert, badge) + `lib/utils.ts`.
- Card lists with a "⋯" actions menu instead of tables; tables only for numeric grids inside `overflow-x-auto`.
- `lib/api.ts` wrapper (same-origin, `x-csrf-token`, `ApiError`) + TanStack Query; `auth/session.ts` (`useMe`, `useSignOut`); `RequireSession` gate in `router.tsx`.
- Tests: `test/render.tsx` (`mockApi`, `renderAt`) and `test/setup.ts`; PWA via `vite.config.ts`.

**Navigation:** tabs **Home · Rigs · Gear · Events · People**; account menu holds **Audit log** and **Settings** (admins), theme, GitHub, sign out. Accent hue changed from TeeMate's green to sky blue.

| RigTracker page | TeeMate pattern |
|---|---|
| Home (placeholder) | `HomePage` + `ThisWeekCard`: repacks due/overdue, upcoming events, quick add |
| Rigs, Gear, People | `UsersPage` card list: search + filter, thumbnail, status `Badge` (repack overdue in destructive), ⋯ menu, add/edit `Dialog` |
| Rig / Person detail | `PlayerPage`: header card, assigned-gear card list, "Assign gear" dialog; `ContactLinks` for people |
| Events | `SchedulePage`: date-grouped list; month view only on `md+` |
| Event detail | `PhotosPage` + `Photos.tsx` grid; `DetailsForm` |
| Settings | `UsersPage` with role menu; block self-demotion |
| Audit | `ActivityPage` timeline, server-side filters, "Load more" |

**Approach:** rewrite page by page on the new stack rather than running antd and Tailwind side by side. At ~3k lines and 9 pages, a mixed state costs more (two resets, specificity fights, half-working dark mode, both bundles) than it saves.
